The five additional MCP tools are `ingest_sources`, `trial_source`,
`get_discovery_status`, `get_job_eligibility`, and `search_eligible_jobs`.
All nine previous tools remain discoverable. Startup permissions independently
grant network trials (`--enable-source-trials`), ingestion (`--enable-ingest`),
and the existing save/preparation operations (`--enable-local-writes`). Default
mode remains read-only. No source/profile modification or submission tool exists.

CLI ingestion/trials delegate to shared discovery services. MCP ingestion uses
the same adapters, filters, canonical score context and deduplication, with
cross-process locking, a 20-source request bound, 180-second ingest workers,
30-second trials, status polling, shutdown cleanup and abandoned-run recovery.
Source upserts, classifications and final counts share a transaction; interrupted
source work rolls back while prior completed sources remain retained.

Eligibility is a separate deterministic service with per-check evidence, missing
facts, concerns and next actions. It uses verified profile facts and explicit
preferences; it does not change canonical scores. MCP preparation rechecks it,
including on bundle reuse. Manual CLI/web draft preparation remains available.
Complete edited packages are retained unchanged; no duplicate save/package events
or application records are introduced.

Experience extraction retains minimum/maximum, preferred status, alternatives,
open upper bounds and evidence. `2–12+ years` has minimum 2, not 12. Explicit title
seniority remains authoritative; internship background text does not reclassify
ordinary engineering roles. New-graduate roles are distinguished from internships.
Provider HTML keeps qualification boundaries; Lever's actual production payload
shape, URLs, workplace type and employment type are retained. Implicit default
support exclusions yield only to explicitly targeted support roles; explicit
source/profile exclusions remain authoritative. No scoring formula/weights changed.

## Architectural assessment

1. **Can Codex refresh sources through Job-Pipe MCP? Yes**, with explicit ingest
   capability, bounded workers and observable run status.
2. **Can Codex trial candidates without canonical insertion? Yes**, for configured
   or cataloged supported sources with explicit trial capability.
3. **Can Job-Pipe separate technical fit from eligibility? Yes**, canonical scores
   and evidence-based three-state assessments remain independent.
4. **Can Codex find, evaluate, save and prepare entirely through MCP? Yes**, as
   verified through real stdio. Real preparation is blocked until eligibility is
   established; the system does not manufacture a shortlist.
5. **Smallest next submission step:** after completing/verifying applicant facts,
   implement one documented provider-specific submission adapter behind a separate
   explicit authorization capability, with per-application consent, idempotency,
   receipt verification and failure reconciliation. Browser form automation and
   unrestricted HTTP are unnecessary for that first authorized integration.

All implementation changes are unstaged. No branch creation/switching, staging,
commit, merge, tag, push, release or external application submission was performed.
